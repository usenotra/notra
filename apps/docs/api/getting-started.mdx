The Notra API is a REST API served from `https://api.usenotra.com`. Everything the dashboard can do with GEO tracking, content, schedules, chats, skills and agent feedback is available over HTTP. The full contract is an OpenAPI 3.1 document at [api.usenotra.com/openapi.json](https://api.usenotra.com/openapi.json).

<CardGroup cols={2}>
  <Card title="REST API" icon="globe">
    Call endpoints directly with `curl` or `fetch`, which works for every endpoint group.
  </Card>
  <Card title="TypeScript SDK" icon="code">
    Use `@usenotra/sdk` for typed requests and responses across the Content, Schedules, Event Triggers, Chats, Skills, Feedback and Agent endpoints.
  </Card>
</CardGroup>

## Quick start

Base URL:

```bash
https://api.usenotra.com
```

Paths are versioned (`/v1/...`, and `/v2/...` for the Agent group). Requests authenticate with a bearer credential, which is either an API key from the dashboard or an OAuth access token from the Notra authorization server. Notra infers the organization from the credential, so the URL has no organization segment.

Check that the API is reachable without a key:

```bash
curl https://api.usenotra.com/v1/status
```

```json
{
  "status": "ok",
  "service": "Notra API",
  "version": "1.0.0",
  "public": true,
  "authentication": {
    "type": "bearer",
    "resource_metadata": "https://api.usenotra.com/.well-known/oauth-protected-resource",
    "guide": "https://www.usenotra.com/auth.md"
  }
}
```

Then make an authenticated request:

<CodeGroup>
```bash cURL
curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.usenotra.com/v1/posts"
```

```typescript fetch
const response = await fetch("https://api.usenotra.com/v1/posts", {
  headers: {
    Authorization: `Bearer ${process.env.NOTRA_API_KEY}`,
  },
});

const data = await response.json();
console.log(data.posts);
```

```typescript SDK
import { Notra } from "@usenotra/sdk";

const notra = new Notra({
  bearerAuth: process.env.NOTRA_API_KEY ?? "",
});

const result = await notra.content.listPosts();

console.log(result.posts);
```
</CodeGroup>

## Create an API key

<Steps>
  <Step title="Open API Keys">
    In the [dashboard](https://app.usenotra.com), open **API Keys** at the bottom of the sidebar, which takes you to `app.usenotra.com/{org-slug}/api-keys`.
  </Step>
  <Step title="Click Create API Key">
    Pick a name, an expiration (no expiry, 7, 30, 60 or 90 days) and the permissions the key needs. Start from one of the presets (MCP Server, SDK, CLI) or choose **Restricted** to set read or write access per resource.
  </Step>
  <Step title="Copy the key">
    Keys start with `ntra_` and the dashboard shows each key only once, so store the value in a server-side environment variable such as `NOTRA_API_KEY`.
  </Step>
</Steps>

[Authentication](/api/authentication) covers scopes, presets and error responses.

<Note>
  Building a CLI, MCP client or agent that acts for a signed-in user? Use OAuth instead of a pasted key. Register a client, run the authorization code flow with PKCE (or the device flow on headless machines) and send the access token in the same `Authorization: Bearer` header, which the Notra MCP server also accepts. [OAuth](/api/authentication#oauth) has the details.
</Note>

<Warning>
  Keep API keys private. If a key ends up in client-side code, anyone can use it
  to burn through your [rate limits](/api/rate-limits), even if the key is
  read-only, so make requests from your backend.
</Warning>

## SDK installation

<CodeGroup>

```bash npm
npm install @usenotra/sdk
```

```bash yarn
yarn add @usenotra/sdk
```

```bash pnpm
pnpm add @usenotra/sdk
```

```bash bun
bun add @usenotra/sdk
```

</CodeGroup>

Initialize the client with your API key:

```typescript
import { Notra } from "@usenotra/sdk";

const notra = new Notra({
  bearerAuth: process.env.NOTRA_API_KEY ?? "",
});

const post = await notra.content.getPost({ postId: "post_abc" });
```

The SDK exposes one namespace per endpoint group: `notra.content`, `notra.schedules`, `notra.eventTriggers`, `notra.chats`, `notra.skills`, `notra.feedback` and `notra.agent`. Notra generates it from the OpenAPI document and publishes it at [github.com/usenotra/typescript-sdk](https://github.com/usenotra/typescript-sdk).

<Note>
  GEO endpoints (projects, prompts, competitors, scans, visibility, gaps, briefs, agent readiness, traffic) are not in the SDK yet. Call them with `fetch` or generate a client from the [OpenAPI document](https://api.usenotra.com/openapi.json).
</Note>

## Responses and errors

Successful responses are JSON. List and detail responses in the Content and GEO groups also include an `organization` object (`id`, `slug`, `name`, `logo`) describing the organization the key belongs to.

Errors are JSON with an `error` message, and authentication failures add a machine-readable `code` and a `recovery` hint:

```json
{
  "error": "Invalid API key",
  "code": "INVALID_API_KEY",
  "recovery": "Send Authorization: Bearer <NOTRA_API_KEY>. See https://www.usenotra.com/auth.md for agent credential discovery."
}
```

| Status | When |
| --- | --- |
| `400` | Validation failed. `error` names the field, for example `limit: Too big: expected number to be <=100`. |
| `401` | Missing, invalid or expired credential (API key or OAuth token). The response also carries a `WWW-Authenticate` header with the OAuth discovery URL. |
| `402` | The organization has no active paid plan or AI credits for a write, or no GEO plan for a GEO endpoint. |
| `403` | The key lacks the scope the endpoint needs. |
| `404` | Resource not found, or an unknown route. |
| `409` | Conflict, for example a duplicate name. |
| `429` | Rate limited. See [Rate Limits](/api/rate-limits). |
| `503` | The authentication or billing service is temporarily unavailable. Retry with backoff. |
