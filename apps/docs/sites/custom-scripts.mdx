Run your own JavaScript on every page of your site and control which origins your pages may load code from. To send visits to Google Analytics 4, PostHog, Plausible or Umami, use an [analytics integration](/sites/integrations/analytics/overview) instead, which needs no script.

## Custom scripts

Every `.js` file outside the content folders runs on every page, whether it's `script.js`, a file in a `scripts/` folder or a file like `analytics.js` at the root. These files work like [custom CSS](/sites/customize/design#your-own-css) for JavaScript, while a `.js` file in `snippets/`, `blog/` or `changelog/` is a component you import instead.

```text
script.js               # runs first
analytics.js            # then every other script, sorted by path
scripts/chat-widget.js
scripts/tracking/hotjar.js
```

Notra loads every script on every page with `defer` from your site's own address, and the scripts run in the order shown above once the HTML has been parsed.

- These files are plain browser JavaScript rather than modules, so `import` and `export` don't work in them. To load a library from another host, use `document.createElement("script")`.
- The build checks the syntax without running your scripts, and a syntax error fails the build and shows the file and line.
- Your MDX can't import these files, so for a component, use a [snippet](/sites/custom-components) in `snippets/` instead.

```js scripts/external-links.js
// Open links to other sites in a new tab.
for (const link of document.querySelectorAll("main a[href^='http']")) {
  if (link.host !== location.host) {
    link.target = "_blank";
    link.rel = "noopener";
  }
}
```

## Content-Security-Policy

Every page comes with a `Content-Security-Policy` header that says where scripts may come from and which servers they may connect to, and Notra builds it from your repository.

- **Scripts** can come from your site, the analytics integrations you turned on and your `allowedOrigins`. Notra allows inline scripts only if they were on the page at build time and hashes each of them, so a script injected later doesn't run.
- **Connections** from `fetch`, beacons and WebSockets may go to your site, your integrations and your `allowedOrigins`.
- The policy doesn't limit **images, styles, fonts, videos and embeds**, so posts can still show images and videos from anywhere.

If your custom scripts or components load code from another host or call an API, add that origin:

```json blog.json
{
  "security": {
    "allowedOrigins": [
      "https://cdn.example-widget.com",
      "https://*.example-widget.com",
      "wss://*.example-widget.com"
    ]
  }
}
```

Origins must start with `https://` or `wss://` and have no path, and `https://*.example.com` covers every subdomain. A `wss://` origin only allows connections rather than scripts, and you can list up to 32 origins.

To turn the policy off entirely:

```json blog.json
{
  "security": { "contentSecurityPolicy": false }
}
```

If a script doesn't run, open your browser's developer console, which lists any request the policy blocked with the origin you need to add.
