Notra can generate content without you starting each run by hand. In **Studio** mode the sidebar has an **Automation** section with **Schedules** and **Events**. Both are rule-based automations you configure once.

## Automation modes

<CardGroup cols={2}>
  <Card title="Scheduled" icon="clock" href="/automation/scheduled">
    Generate content daily, weekly or monthly from activity in a lookback window
  </Card>

  <Card title="Event-Based" icon="bolt" href="/automation/event-based">
    Generate content when a GitHub release is published or code lands on the default branch
  </Card>
</CardGroup>

## How schedules and events work

<Steps>
  <Step title="Pick sources">
    Choose the GitHub repositories the automation should read. Schedules also pull completed work from every enabled Linear integration in the workspace.
  </Step>

  <Step title="Pick an output format">
    Choose one format per automation: changelog entry, blog post, LinkedIn post, tweet or image.
  </Step>

  <Step title="Pick a brand identity">
    Use the workspace default or pin a specific brand identity. It sets the tone, audience and custom instructions.
  </Step>

  <Step title="Generate and review">
    The run analyzes the activity, writes the content and saves it as a draft. With auto-publish on, it publishes the post instead. Review it under **Content**.
  </Step>
</Steps>

## Supported output types

Schedules and event triggers support the same five formats:

| Format | Value in the API | Auto-publish |
| --- | --- | --- |
| Changelog entry | `changelog` | Yes |
| Blog post | `blog_post` | Yes |
| LinkedIn post | `linkedin_post` | No |
| Tweet (X) | `twitter_post` | No |
| Image | `image` | No |

Auto-publish marks changelogs and blog posts as published instead of saving them as drafts. Notra always saves social posts and images as drafts for you to review and post.

<Note>
  Investor updates exist as a content type for manual generation, but you cannot select them for schedules or event triggers.
</Note>

## Billing

Automated runs count against the same plan quotas as manual generation. Changelogs and blog posts use the long-form post quota. LinkedIn posts and tweets use the social post quota. Images use the image generation quota. When a quota is used up, AI credits cover the run if you have them. If neither is available, the run stops and workspace owners receive an email. Add credits or upgrade to resume. See [Billing](/organization/billing).

## Choosing the right mode

<Tabs>
  <Tab title="Event-Based">
    **Best for:**

    * Immediate responses to releases
    * Changelog entries when code lands on the default branch
    * Announcing new features as they ship

    **Example scenarios:**

    * Generate a LinkedIn post when you publish a GitHub release
    * Create a changelog entry for every push to `main`
  </Tab>

  <Tab title="Scheduled">
    **Best for:**

    * Regular content cadence (daily, weekly, monthly)
    * Digest-style updates covering multiple changes
    * Consistent social media presence

    **Example scenarios:**

    * Weekly product update LinkedIn posts every Monday
    * Monthly changelog roundups on the 1st
    * A daily social image during a launch week
  </Tab>
</Tabs>

## Managing automations

Each schedule or event trigger can be:

* **Enabled or paused**: the Schedules and Events pages split automations into **Active** and **Paused** tabs. Pausing keeps the configuration.
* **Edited**: change sources, format, brand identity, timing or auto-publish.
* **Run now**: you can run schedules on demand from the row menu. Event triggers only fire from GitHub.
* **Deleted**: removed permanently.

Notra rejects a second schedule or trigger with exactly the same configuration in the same workspace.

**Notifications.** Under **Settings > Notifications** you can be emailed when automated content is created, when generation fails and when a run is skipped because there was nothing worth writing about. **Settings > Logs** lists integration events (such as GitHub webhook deliveries) with their delivery status.

<Info>
  You can combine modes. For example, use an event trigger for release announcements and a weekly schedule for a progress digest.
</Info>
