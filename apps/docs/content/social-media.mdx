Notra generates LinkedIn and X posts from your GitHub and Linear activity, and you edit them with the content agent and publish them to your connected accounts from the editor.

## Supported platforms

**LinkedIn** (`linkedin_post`)\
Posts of around 800 characters for professional networking and thought leadership.

**X** (`twitter_post`)\
Posts of 280 characters or fewer, although the editor allows up to 25,000 characters if the connected account is verified (Premium or Business).

Both count as **social posts** in billing, and social posts are unlimited on every paid plan.

## Generating social posts

<Steps>
  <Step title="Open the create dialog">
    Switch the sidebar to **Studio**, open **Content** and click **New post**.
  </Step>

  <Step title="Formats">
    Select **LinkedIn post**, **Tweet** or both, and combine them with a changelog or blog post in the same run if you like. Pick a lookback window and toggle **Pull Requests**, **Commits** and **Releases**.
  </Step>

  <Step title="Activity">
    Choose repositories and Linear integrations, then deselect anything you do not want mentioned. Social posts work best when you narrow the selection to one meaningful change.
  </Step>

  <Step title="Identity">
    Choose the brand identity that should write the post, since the writer reads that identity's reference posts first to match your voice.
  </Step>
</Steps>

Schedules and event triggers can also generate social posts with `outputType` set to `linkedin_post` or `twitter_post`. Notra always saves these as drafts, because auto-publish is only available for changelogs and blog posts. See [Scheduled Automation](/automation/scheduled).

<Warning>
  If there is no meaningful activity in the lookback window, the writer skips the run instead of forcing a post, and scheduled runs report this as skipped.
</Warning>

## LinkedIn posts

### Structure

Every LinkedIn post follows this flow:

<Steps>
  <Step title="Hook (2 lines)">
    **Line 1**: a bold statement that earns attention without overpromising\
    **Line 2**: a rehook that challenges, twists or sharpens line 1
  </Step>

  <Step title="Insight or story">
    What you built, discovered or learned
  </Step>

  <Step title="Lesson">
    Why it matters and what changed
  </Step>

  <Step title="Takeaway">
    A clear ending that prompts reflection or a reply
  </Step>
</Steps>

### Content rules

* Around 800 characters
* One core idea, at most two supporting updates
* No hashtags and no emojis
* No PR numbers and no GitHub links
* Only line breaks and simple bullets for formatting
* Meaningful bug fixes can carry a post when they clearly improve user experience, reliability, security or performance

### Example

```text
Shipped something I've been thinking about for months.

We just released cache component support with actionable error
guidance for our developer tools.

The problem we kept hearing: developers were hitting cryptic errors
when using auth calls in cached contexts, with no clear path forward.

Now the runtime catches these issues early and provides:
- Clear migration guidance
- The exact usage pattern needed
- Zero guesswork

Small change. Big impact on developer experience.

What's the most frustrating error message you've encountered recently?
```

## X posts

### Content rules

* 280 characters or fewer, aiming for 100 to 250
* No hashtags and no emojis
* No PR numbers and no GitHub links
* One idea per post

The editor shows a live character count against the limit of the account you are posting from.

## Tone

Notra writes posts in the tone profile of the selected brand identity: **Conversational**, **Professional**, **Casual** or **Formal**, which you configure under **Studio > Brand Identity**. See [Brand Voice](/concepts/brand-voice).

<Tip>
  Add real posts you have written as **References** on the brand identity so the social writer can read them before drafting. References do more than any other setting to make posts sound like you.
</Tip>

## Connecting your accounts

Publishing from Notra needs a connected account.

<Steps>
  <Step title="Open Analytics">
    In **Studio**, open **Analytics**.
  </Step>

  <Step title="Connect">
    Click **Connect X** or **Connect LinkedIn**, and Notra sends you to the platform to authorize it before returning you to the dashboard.
  </Step>

  <Step title="Pick a LinkedIn page (optional)">
    If your LinkedIn login manages several pages or organizations, Notra asks which one to connect.
  </Step>
</Steps>

Connected accounts belong to the organization, so any member can publish to them. You can reconnect an account from the same page if a token expires.

<Note>
  The connection link is valid for 10 minutes, and the user who started it must complete it.
</Note>

## Publishing

Open a LinkedIn or X post in the editor and click **Post to LinkedIn** or **Post to X**.

<Steps>
  <Step title="Preview">
    A dialog shows the post as it will appear, with the connected account's name and avatar, and you can make final edits here. If several accounts are connected, pick the one to publish from.
  </Step>

  <Step title="Publish">
    Click the publish button, and Notra sends the post to the platform and waits for confirmation. On success, it shows a link to the live post.
  </Step>

  <Step title="Save as a reference (optional)">
    After publishing, you can add the post as a reference to one of your brand identities so future posts learn from it.
  </Step>
</Steps>

Publishing to a platform is separate from the post status in Notra. The **Publish** button in the editor toolbar only changes the status from `draft` to `published` and does not post anything to X or LinkedIn.

If no account is connected, the button opens the platform's compose window in a new tab instead. For LinkedIn, Notra copies the post text to your clipboard so you can paste it.

<Warning>
  X and LinkedIn reject posts that duplicate something the account recently published, so edit the text before publishing it a second time.
</Warning>

## Analytics

After you connect an account, **Studio > Analytics** shows engagement rate, followers, impressions and interactions for the selected date range, along with a leaderboard of your posts and a page per account. Notra matches posts published from Notra to their analytics automatically.

## Editing social posts

Use the content agent in the editor to refine a draft:

**Adjust the hook**\
"Make the opening more surprising"\
"Start with a specific problem statement"

**Change the focus**\
"Focus more on the performance impact"\
"Highlight the technical challenge we solved"

**Refine the tone**\
"Make this more conversational"\
"Simplify the language"

**Improve engagement**\
"Add a question at the end"\
"Include a specific metric"

<Tip>
  Keep your edits short, because social posts should be short and easy to read on mobile.
</Tip>

## Best practices

### One core idea per post

Pick the most interesting update and go deep on it.

**Good**: Focus on one feature with clear impact\
**Poor**: List 10 different updates from your changelog

### Lead with impact, not implementation

**Good**: "We reduced API response time by 60%"\
**Poor**: "We implemented request coalescing and caching"

### Use specific numbers

**Good**: "Reduced build time from 8 minutes to 90 seconds"\
**Poor**: "Significantly improved build performance"

### End with a question

**Good**: "What's the most frustrating error message you've encountered?"\
**Poor**: "Check out our changelog for more details."

### Match your activity level

If you ship weekly, post weekly, and if you ship monthly, post monthly. Notra will not invent news when there is none.

## Common pitfalls

### Changelog dumps

**Poor**: "This week we shipped 15 PRs including cache support, email verification, state management, and scrollbar styling..."

**Good**: "We shipped cache component support with actionable error guidance."

### Over-promotion

**Poor**: "Our amazing new feature is revolutionary and game-changing!"

**Good**: "Solved a problem that's frustrated developers for years."

### Corporate speak

**Poor**: "We're excited to announce that we've leveraged cutting-edge technologies to deliver best-in-class solutions..."

**Good**: "We built a thing that makes auth calls in cached contexts actually work."

## Scheduling social posts

Create separate schedules for different cadences:

<Visibility for="agents">

```json
{
  "name": "Weekly LinkedIn update",
  "sourceType": "cron",
  "sourceConfig": {
    "cron": { "frequency": "weekly", "hour": 9, "minute": 0, "dayOfWeek": 1 }
  },
  "targets": { "repositoryIds": ["repo_123"] },
  "outputType": "linkedin_post",
  "outputConfig": { "brandVoiceId": "bv_123" },
  "lookbackWindow": "last_7_days",
  "enabled": true,
  "autoPublish": false
}
```

</Visibility>

Generated posts appear as drafts in **Content**. Open one, review it and publish it to the connected account from the editor.

<Visibility for="agents">

<Tip>
  Find repository IDs in **Integrations > GitHub**, or list them with `GET /v1/integrations`.
</Tip>

</Visibility>
